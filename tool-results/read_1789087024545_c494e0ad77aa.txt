     7→## Project Overview
     8→
     9→A production-ready, free/low-cost business lead generation platform built on Next.js 16
    10→+ Prisma (SQLite) + socket.io mini-service worker. Discovers REAL public business leads
    11→from permitted sources (OpenStreetMap Overpass API, public website contact pages) — no
    12→mock data, no dummy records.
    13→
    14→### Architecture
    15→- **Frontend**: Single-page app at `/` (App Router) with client-side section navigation.
    16→  Sections: Dashboard, Find Leads, Campaigns, Leads, Exports, Analytics, Sources,
    17→  Suppression List, Settings.
    18→- **API**: Next.js API routes under `/src/app/api/*` (REST).
    19→- **Worker / Realtime**: Mini-service on port 3003 (`mini-services/lead-worker`)
    20→  running socket.io + background discovery pipeline. Campaigns execute here.
    21→- **Database**: Prisma + SQLite at `db/custom.db`.
    22→- **Real sources**: OpenStreetMap Overpass API (business POIs with phones/websites),
    23→  Nominatim (geocoding), public website contact-page scraping (SSRF-protected).
    24→
    25→### Tech Stack
    26→Next.js 16, TypeScript, Tailwind CSS 4, shadcn/ui (New York), Prisma, socket.io,
    27→cheerio (HTML parsing), libphonenumber-js (E.164), xlsx (export), recharts (analytics).
    28→
    29→### Key Constraints
    30→- Only `/` route is user-visible (SPA with internal nav).
    31→- API requests must be relative paths; cross-port via `?XTransformPort=3003`.
    32→- z-ai-web-dev-sdk only in backend.
    33→- SSRF protection on all outbound website fetches.
    34→- NO mock/dummy leads. Every lead from a real permitted source.

   522→Root Cause Analysis:
   523→1. **CRITICAL BUG**: Overpass bbox query was missing parentheses — emitted `node["tag"]52.3,13.2,...` (invalid syntax, HTTP 400 parse error) instead of `node["tag"](52.3,13.2,...)`. This caused ALL bbox-based extractions to fail.
   524→2. **Timeout too short**: 6-8s fetch timeout was insufficient for Overpass API on large cities (Berlin restaurants need ~10s).
   525→3. **Multi-tag queries too heavy**: Querying 7 tags at once exceeded the time budget.
   526→4. **Vercel 10s function limit**: Hobby plan limited serverless functions to 10s, not enough for Overpass + geocoding + processing.
   527→
   528→Fixes Applied:
   529→- **bbox syntax**: Wrapped bbox coordinates in parentheses in `buildOverpassQuery()` — `node["tag"](s,w,n,e)`.
   530→- **vercel.json**: Increased `maxDuration` to 60s for worker/tick route (Pro plan).
   531→- **Overpass fetch timeout**: 15s per query (was 6-8s).
   532→- **Tick budget**: 45s (was 8s).
   533→- **Single-tag queries**: Try each OSM tag individually (was multi-tag in one query) — faster, more reliable.
   534→- **Smaller bbox**: 0.3°×0.3° (~33km) centered on city (was 0.4° or full admin boundary).
   535→- **kumi.systems first**: Reordered Overpass endpoints — kumi is more reliable from Vercel than overpass-api.de.
